# แผนพัฒนา Gang Desk

## ขอบเขตและข้อกำหนดที่ยึดถือ

เว็บไซต์นี้เป็นระบบจัดการแก๊งภาษาไทย เขียนด้วย **PHP 8.3** และใช้งานผ่านเว็บ โดยไม่สร้างรายชื่อสมาชิก รายการส่งของ หรือข้อมูลจำลองใด ๆ ในระบบ ข้อมูลปฏิบัติการของแก๊งทั้งหมดจะอยู่ใน Discord และการแจ้งเตือนทุกประเภทจะส่งไปยัง Discord เท่านั้น

การตั้งค่าการทำงานของแก๊ง เช่น ช่อง Discord ที่ใช้บันทึกข้อมูล ชื่อแก๊ง โลโก้ พื้นหลัง รอบส่งของ และช่องแจ้งเตือน จะจัดการจากหน้าเว็บสำหรับหัวแก๊ง/รองหัวแก๊ง ไม่ต้องพิมพ์คำสั่งตั้งค่าใน Discord อย่างไรก็ตาม Discord บังคับให้สร้าง Discord Application และเชิญบอตเข้าดิสคอร์ดก่อนใช้งานครั้งแรก ซึ่งเป็นขั้นตอนภายนอกที่หลีกเลี่ยงไม่ได้

## ทางเลือกด้านการออกแบบ

1. **Cyber Control Room** — แผงควบคุมสีเข้มแบบเกมมิ่ง มีเส้นแสงและพื้นผิวกระจก; ความน่าจะเป็นที่เลือกโดยสุ่ม: 0.07
2. **Midnight Glass Ledger** — แดชบอร์ดกระจกโปร่งแสงบนพื้นหลังเปลี่ยนได้ เน้นข้อมูลอ่านง่าย; ความน่าจะเป็นที่เลือกโดยสุ่ม: 0.05
3. **Neon Street Terminal** — แรงบันดาลใจจาก UI เมืองไซเบอร์พังก์ ใช้ตัวอักษรใหญ่และแอนิเมชันเด่น; ความน่าจะเป็นที่เลือกโดยสุ่ม: 0.03

**แนวทางที่เลือก: Midnight Glass Ledger ผสาน Cyber Control Room**

- **Design Movement:** ระบบปฏิบัติการแก๊งแนว dark-glass ที่ให้ความรู้สึกเป็นศูนย์บัญชาการ มากกว่าตารางจัดการทั่วไป
- **Core Principles:** ลำดับข้อมูลชัดเจน, การกระทำสำคัญเข้าถึงเร็ว, สิทธิ์ผู้ใช้มองเห็นได้อย่างสุภาพ, และหน้าว่างไม่แสดงข้อมูลสมมติ
- **Color Philosophy:** ถ่านเข้ม/น้ำเงินดำเป็นพื้นเพื่อรองรับภาพพื้นหลังของผู้ใช้ และใช้ม่วงไฟฟ้าเป็นสีเอกลักษณ์สำหรับสถานะและปุ่มหลัก พร้อมสีเขียว/ส้ม/แดงเฉพาะความหมายของสถานะ
- **Layout Paradigm:** แถบนำทางแนวตั้งแบบ command rail ที่ยุบได้ เชื่อมกับพื้นที่เนื้อหาที่จัดเป็นชั้นข้อมูล ไม่ล็อกทุกหน้าไว้กับกริดกึ่งกลาง
- **Signature Elements:** ขอบกระจกเรืองแสงบาง, แถบสรุปสถานะแบบ pulse, และบัตรข้อมูลที่เคลื่อนไหวเล็กน้อยเมื่อชี้
- **Interaction Philosophy:** ยืนยันผลการทำรายการด้วยสถานะที่อ่านง่าย การกระทำที่มีสิทธิ์สูงมี confirm dialog และ UI จะซ่อน/ปิดสิ่งที่ไม่มีสิทธิ์แทนการปล่อยให้กดแล้วล้มเหลว
- **Animation:** Transition 160–240ms, hover ยกบัตรเล็กน้อย, skeleton loading สำหรับข้อมูล Discord; เคารพ `prefers-reduced-motion`
- **Typography System:** Noto Sans Thai สำหรับข้อความไทย และ Space Grotesk สำหรับตัวเลข/หัวข้อสถานะ โดยมีลำดับชั้นที่อ่านได้ทั้งมือถือและเดสก์ท็อป
- **Brand Essence:** “ศูนย์กลางการปฏิบัติการของแก๊ง ที่เชื่อมทุกงานไว้กับ Discord” — มั่นใจ, คล่องตัว, เป็นทีม
- **Brand Voice:** กระชับแบบปฏิบัติการ เช่น “เช็คชื่อวันนี้ให้พร้อม” และ “บันทึกส่งถึง Discord แล้ว”
- **Wordmark & Logo:** เครื่องหมายรูปโล่ทรงเหลี่ยมมีจุดสัญญาณ พร้อม wordmark GANG DESK; ผู้ดูแลเปลี่ยนโลโก้ในเว็บได้
- **Signature Brand Color:** Arc Violet `#8B5CF6`

## สถาปัตยกรรม

### PHP และการให้บริการ

- ใช้ PHP 8.3 แบบไม่พึ่ง framework เพื่อให้เป็นโค้ด PHP ที่นำไปติดตั้งต่อได้ง่าย
- แยก controller, service, view และ asset ชัดเจน; ให้ Apache/PHP ใน Docker เป็น production runtime และ PHP built-in server สำหรับ Preview
- มี route manifest ครบก่อนเปิด development server และ health endpoint ที่เข้าถึงได้โดยไม่ต้องล็อกอิน
- ไม่มีข้อมูลธุรกิจในไฟล์, session, หรือ filesystem ของ container; cache ระยะสั้นในหน่วยความจำใช้เพื่อประสิทธิภาพเท่านั้น

### Discord เป็นแหล่งข้อมูลหลัก

- ใช้ Discord OAuth2 เพื่อระบุตัวตนและดึง Discord username/avatar ของผู้ใช้
- ใช้ Discord Bot Token บน server เท่านั้นเพื่อยืนยันว่าเป็นสมาชิก guild, อ่าน/เขียนข้อมูล และส่งแจ้งเตือน
- บอตจะบันทึก event ที่มี schema ชัดเจนเป็น JSON ลงช่องข้อมูลส่วนตัวใน Discord (เช่น `gangdesk-data`) และบันทึกการตั้งค่าเป็น record แยกต่างหากใน Discord
- การดึงข้อมูลหน้าเว็บจะอ่าน event จาก Discord แล้วรวมผลบน server โดยไม่ใช้ MySQL เป็นฐานข้อมูลแก๊ง; ไฟล์หลักฐานและรูปโลโก้/พื้นหลังที่อัปโหลดผ่านเว็บจะส่งเป็น attachment ของ Discord
- มี validation, schema version, UUID, user ID Discord, timestamp และ audit trail ในทุก event เพื่อคัดแยก/ตรวจสอบข้อมูล; การแก้ไขจะสร้าง revision ใหม่แทนการลบประวัติ
- แจ้งเตือน check-in, ส่งของ, เบิกของ, แจ้งลา, เปลี่ยนแปลงสิทธิ์ และการแจ้งเตือนกำหนดเองจะส่งไปยัง notification channel ที่เลือกในหน้า Settings เท่านั้น ไม่มี notification center หรืออีเมล
- ข้อจำกัด: Discord ไม่ใช่ relational database จึงเหมาะกับแก๊งขนาดเล็กถึงกลาง ระบบจะใช้การแบ่งหน้าและ cache เพื่อรองรับประวัติที่เพิ่มขึ้น; ข้อมูลไม่ถูกทำสำเนาไปยังฐานข้อมูลแอป

### สิทธิ์และความปลอดภัย

- สมาชิกล็อกอินด้วย Discord เท่านั้น: OAuth state/nonce แบบใช้ครั้งเดียว, redirect path คงที่, session cookie `Secure; HttpOnly; SameSite=None`, CSRF token และ session rotation
- ตรวจสอบ Discord guild membership ทุกครั้งที่สร้าง session; ไม่สร้างบัญชีปลอมหรือ bypass login ในโหมดพัฒนา
- บัญชีหัวแก๊งต้องผ่าน Discord OAuth และกรอก PIN ในหน้า `/หัวแก๊ง` เพิ่มเติม; ระบบไม่แสดง PIN ที่ใดใน UI, ไม่ใส่ใน source code และไม่บันทึก PIN แบบ plaintext ใน Discord
- PIN เริ่มต้นรับผ่านช่อง secret ที่ปลอดภัยเป็น `HEAD_PIN` และเข้าได้เฉพาะผู้ที่มี Discord ID ของหัวแก๊งตามการตั้งค่า; หลังตั้งค่าแล้ว หัวแก๊งสามารถเปลี่ยน PIN ในหน้า Settings ได้ โดยบันทึกเฉพาะ hash ใน Discord
- บทบาทตายตัว 4 ระดับ: หัวแก๊ง, รองหัวแก๊ง, ที่ปรึกษา, สมาชิก โดยเก็บ role assignment เป็น record ใน Discord
- หัวแก๊งและรองหัวแก๊งเท่านั้นที่เข้าหน้า Settings, แก้ชื่อ IC/ชื่อแสดงของสมาชิก, แต่งตั้ง/ปรับบทบาทตามนโยบายที่กำหนด และนำสมาชิกออกได้; การนำออกเป็นสถานะถูกนำออกพร้อม audit event ไม่ลบประวัติ
- สมาชิกแก้ข้อมูลโปรไฟล์ของตนเองได้ (ชื่อแสดง, คำแนะนำตัว, รูปโปรไฟล์ที่อัปโหลด) โดย avatar Discord เป็นค่าเริ่มต้น

## หน้าจอและการทำงาน

1. **หน้าเข้าสู่ระบบ** — ปุ่ม “เข้าสู่ระบบด้วย Discord”, เหตุผลการใช้ข้อมูล และปุ่มสำหรับหัวแก๊ง; ไม่มีบัญชีหรือสมาชิกตัวอย่าง
2. **หน้าเข้าสู่ระบบหัวแก๊ง** — ใช้ Discord session ที่ผ่านการตรวจ guild แล้ว + PIN; อนุญาตเฉพาะ Discord ID ที่ตั้งเป็นหัวแก๊ง
3. **ตั้งชื่อ IC ครั้งแรก** — บังคับกรอกชื่อ IC หลังล็อกอินสำเร็จก่อนใช้งานโมดูลอื่น
4. **แดชบอร์ด** — สรุป check-in วันนี้, สถานะส่งของสัปดาห์, คำขอเบิกของ/แจ้งลาที่รอดำเนินการ และลิงก์งานด่วน โดยว่างเปล่าจนกว่าจะมีข้อมูลจริง
5. **เช็คชื่อรายวัน** — check-in ครั้งเดียวต่อวัน, ดูเวลาเช็คและสถานะของตน; ผู้ดูแลดูรายชื่อเช็ค/ไม่เช็คตามวันที่
6. **สมาชิกแก๊ง** — รายชื่อ, โปรไฟล์ Discord/โปรไฟล์ที่ผู้ใช้แก้เอง, IC, บทบาท, สถานะสมาชิก และเบอร์ในเกม; มีการควบคุมแก้ไข/นำออกตามสิทธิ์
7. **ส่งของแก๊ง (รายสัปดาห์)** — สร้างบันทึกส่งของสำหรับสัปดาห์, ระบุรายการ/จำนวน/หมายเหตุ และแนบหลักฐาน
8. **รายชื่อส่งของและหลักฐาน** — ค้นตามสัปดาห์/สมาชิก/สถานะ, เปิดประวัติ record และลิงก์ไฟล์แนบจาก Discord
9. **เบิกของแก๊ง** — สร้างคำขอเบิก ระบุรายการ จำนวน เหตุผล และติดตามสถานะอนุมัติ/ปฏิเสธตามสิทธิ์
10. **แจ้งลา** — เลือกช่วงวัน เหตุผล และติดตามคำขอ; ส่งแจ้งเตือนไป Discord เมื่อสร้างหรือเปลี่ยนสถานะ
11. **รายงานขาดเช็คชื่อ** — คำนวณจำนวนวันไม่เช็คชื่อรายคนจากข้อมูล Discord โดยแยกวันที่ได้รับการอนุมัติลา
12. **สถิติรวม** — สรุปรายวันของ check-in, อัตราการเช็คชื่อ, ความครบถ้วนในการส่งของรายสัปดาห์, รายการเบิกของ และวันลาของทีม พร้อมตัวกรองช่วงเวลา
13. **เบอร์ในเกม** — รายการเบอร์ที่สมาชิกยินยอมให้ทีมดู พร้อมสิทธิ์การแก้ไขตนเอง/ผู้ดูแลตามบทบาท
14. **Settings (เฉพาะหัวแก๊ง/รองหัวแก๊ง)** — ชื่อ/โลโก้/พื้นหลัง, ID ช่องข้อมูลและช่องแจ้งเตือน, รอบส่งของรายสัปดาห์, วันเช็คชื่อ, นโยบายการอนุมัติ, Discord ID หัวแก๊ง, ผู้ดูแล/บทบาท และข้อความแจ้งเตือน
15. **โปรไฟล์ของฉัน** — แก้ข้อมูลที่เป็นของตนเองและเลือกใช้ avatar Discord หรือรูปโปรไฟล์แบบกำหนดเอง

## ข้อมูลเชื่อมต่อที่ต้องใช้ก่อนเปิดใช้งานจริง

คีย์ทั้งหมดจะรับผ่านฟอร์ม secret ที่ปลอดภัย ไม่ใส่ในแชต โค้ด หรือ Git:

- `DISCORD_CLIENT_ID` และ `DISCORD_CLIENT_SECRET` จาก Discord Application สำหรับ OAuth2
- `DISCORD_BOT_TOKEN` สำหรับบอตที่ได้รับเชิญเข้า guild พร้อมสิทธิ์อ่าน/ส่งข้อความและแนบไฟล์ในช่องที่กำหนด
- `HEAD_PIN` สำหรับ PIN เริ่มต้นของหัวแก๊ง (ตั้งโดยเจ้าของผ่านฟอร์มลับ ไม่แสดงกลับและเปลี่ยนภายหลังได้จาก Settings)
- ค่า Discord ที่ไม่ใช่ secret เช่น Guild ID, Data Channel ID และ Notification Channel ID จะกรอก/แก้ผ่านหน้า Settings หลังหัวแก๊งเข้าใช้งานได้

## ลำดับการทำงาน

1. ได้รับการยืนยันแผนนี้
2. สร้างโครง PHP, ธีม responsive, route manifest, Docker และ health endpoint โดยไม่เติมข้อมูลตัวอย่าง
3. สร้าง OAuth Discord, session/CSRF, PIN gate และระบบสิทธิ์
4. สร้าง Discord event store, การแจ้งเตือน Discord และหน้า Settings สำหรับ binding ของ guild/channel
5. สร้างทุกโมดูลการจัดการแก๊งและสถิติจากข้อมูลจริงของ Discord
6. ตรวจ PHP syntax, policy/aggregate tests, health endpoint และเส้นทางที่กำหนด
7. เก็บเป็น checkpoint; จะไม่เผยแพร่สาธารณะหากไม่ได้รับคำสั่ง
